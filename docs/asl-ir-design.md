# ASL IR Design

**Status:** design record, not implemented. Supersedes the earlier draft instruction sets
(the `SETPADS`/`ATTEMPT`/`FORK`/`ARM`/`SELECT` family).

This document records the low-level IR that ASL is lowered to, and — more importantly — **why
each instruction exists**. The instruction set is not designed directly; it is *derived* from a
reference implementation of ASL semantics written in a high-level language (§8). Every
instruction in §4 can be pointed back to a line of that reference.

Reference implementations consulted: `third_party/asl-ir-demo/` (see §7).

---

## 1. Purpose

### 1.1 Goals

- **G1 — Semantics fixed in the IR.** What a program does must be readable off the instruction
  stream. The interpreter's version must not silently change the behaviour of an already
  persisted program.
- **G2 — Mechanism only in the runtime.** The runtime implements primitives; the compiler
  composes shapes. Domain rules (ASL's retry backoff, Map tolerance arithmetic, error-name
  matching) belong to the program, not to a `switch` branch in the interpreter.
- **G3 — No interpreter knowledge of resources.** Cancellation must not require the runtime to
  know which resources are attached to a frame. Resource policy is data (a `kind` table);
  resource lifetime is a scope on the frame.
- **G4 — Cleanup derivable from persisted state only.** Nothing that vanishes on a crash
  (call stack, `defer`, an in-memory resource table) may be needed to clean up.
- **G5 — Minimal, orthogonal instruction set.** Near-identical instructions are a signal that an
  abstraction is missing, not that two instructions are needed.

### 1.2 Non-goals

- Not a bytecode with its own arithmetic VM beyond the constrained `CALC` expression language
  (§4.2). `CALC` must not fail, must not suspend, must not touch the outside world.
- Not a compiler implementation plan (see §9 for the phased work).
- Not the durability/CCES model — see `Architecture.md` and
  `durable-execution-recovery-design.md`.

## 2. The Three Criteria

Every decision below is generated by these three rules. When an instruction's fate is unclear,
apply them rather than taste.

### 2.1 Legality: expanded by the compiler vs. implemented by the runtime

> An instruction whose semantics are realised by **the compiler expanding it into other
> instructions** is a legitimate *shape*. An instruction whose semantics live in **a runtime
> `switch` branch** is domain semantics hidden in the interpreter, and is illegal.

The decisive argument is G1: a rule implemented in the runtime changes an already-persisted
program's behaviour when the interpreter is upgraded. ASL changing its tolerance rounding, its
backoff formula, or the default `TimeoutSeconds` must be a **recompile**, not a runtime upgrade.

Shapes are not defects. `if` / `for` / `?` / `select` all have to be written in a high-level
language too. The defect is only in *where the expansion happens*.

### 2.2 `CALC`'s three prohibitions

The compiler-generated expression language may not **fail**, may not **suspend**, and may not
**touch the outside world**. Satisfying all three is what makes it safe to keep in the program.

### 2.3 Cleanup must be derivable from persisted state

Cancellation can arrive at any `pc` (there is no `pc` for `StopExecution`), so cleanup cannot be
"the thing that happens when the function returns". It must be reachable from data the frame
carries.

## 3. State Model

```
Frame
  pc          program counter (or: re-run from the last suspension point — see OPEN-3)
  regs        register file, frame-scoped (not state-scoped)
  scopes      scope stack, LIFO, one level per state
  state       current state name, visit counter, attempt counter, status
  pads        cleanup landing pad (data: external cancel has no pc)

Register values (serialized with a type tag)
  JSON value | error object | handle | group | message
  Without a tag, a JSON round-trip turns int into float64 and a struct into a map.

Handle  =  one external resource or one child frame
  key, kind, state(running|cancel_requested|cancelled|completed), reg, value, err
  kinds[kind] = { cleanup actions, NeedAck }        <- policy as data
    task_sync      -> CancelTask                       NeedAck
    task_callback  -> InvalidateToken + CancelTask     NeedAck
    timer          -> (nothing)
    child          -> SignalCancel                     NeedAck (the ack is `child_exited`)

Scope   a set of handles; owns their lifetime; one per state
Group   a value in a register = handle set + per-item result slots + counters + tolerance params
Message / Signal   kept separate: messages go to a mailbox (WAIT selects among them);
                   signals are delivered immediately (cancellation)
```

**The single resource abstraction is the handle.** An external task, a timer and a child frame
are all handles, and `SCOPE_CLOSE` treats them alike. This is what makes G3 satisfiable: the
runtime walks a scope (bounded bookkeeping), it does not know what the resources are.

## 4. Instruction Set

21 instructions (`MOV` is sugar; 20 de-sugared).

### 4.1 Entry and registers

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `ENTER` | `"State", cleanup=L?` | State boundary and safe point: clear `%err`/`%res`, `attempt=0`, `visit++`, write the cleanup landing pad. Omitted pad ⇒ the frame has nothing to clean up and cancel terminates it immediately. | seq |
| `MOV` | `%d, %s` | Copy. Sugar for `CALC`; normally optimised away. | seq |
| `ASSIGN` | `%v` | Commit the evaluated variable table into the scope. Takes effect **at state exit**. | seq |

### 4.2 Evaluation

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `EVAL` | `%d, expr, !L` | Evaluate user JSONata. Result is recorded in the `Recorder` (call order included). Failure goes to the lexical error edge `!L`. | seq |
| `CALC` | `%d, expr` | Compiler-generated pure computation: field access, indexing, arithmetic, comparison, error construction. May not fail, may not suspend, may not touch the outside world (§2.2). | seq |

`CALC` is what absorbs the whole `FORK_*` family (§7.1) and the retry backoff arithmetic.

### 4.3 Resources

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `START_TASK` | `%h, "resource", %args` | Create a handle; `StartTask` goes to the outbox. | seq |
| `START_TIMER` | `%h, %secs` | Create a handle; `StartTimer` goes to the outbox. | seq |
| `SCOPE_OPEN` | `%s` | Push a scope. Handles created afterwards register into it. | seq |
| `SCOPE_CLOSE` | `%s` | Pop; issue cleanup for every live handle per its `kinds` entry. **If any live handle has `NeedAck`, the frame suspends until all acknowledgements arrive.** | seq / susp |
| `CANCEL` | `%h` | Request cancellation of a single handle. | seq |

### 4.4 Concurrency

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `GROUP_NEW` | `%g, %n, maxConc, tol, entries` | Create a group. **Map and Parallel share this instruction**; they differ only in operand values (§7.2). | seq |
| `SPAWN` | `%h, %entry, %input` | Create one child frame → a handle. The outer variable scope is **snapshotted**, not captured. | seq |

One `SPAWN` creates exactly one child. The concurrency limit is a comparison in the program plus
a retry on each child exit — **not** a semaphore resource (§8.2).

### 4.5 Suspension

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `WAIT` | `%who, %msg, srcs...` | Suspend until one source is ready. A source is a **handle** or a **message kind**. Returns *which* source won (and the message, if a message source won) — not the value. | **susp** |
| `UNWRAP` | `%v, %h, !L` | Extract a completed handle's value; if the handle is an error, take the lexical edge `!L`. | seq |

`WAIT` returning *which* rather than the value is deliberate: `WAIT` then needs no knowledge of
error semantics or result shapes.

### 4.6 Control flow

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `BR` | `%c, T, F` | Conditional jump. | seq |
| `JMP` | `L` | Unconditional jump. | seq |
| `MATCH` | `%err, pats, T, F` | ASL error-name matching, including `States.ALL` not matching `States.Runtime` / `States.DataLimitExceeded`. De-sugars to `CALC` + `BR` (§OPEN-7). | seq |

### 4.7 Termination

| Instruction | Operands | Semantics | Control |
|---|---|---|---|
| `RAISE` | `%err, !L` | Throw to this state's error edge (Retry / Catch). | term |
| `THROW` | `%err` | Uncatchable failure; terminates this frame. A root frame's `THROW` fails the execution. | term |
| `HALT` | — | This frame succeeds, output is `%in`. | term |
| `ABORT` | — | This frame ends **cancelled**. The default end of a cleanup landing pad. | term |

## 5. Macros (compiler expansion, not primitives)

| Macro | Expands to |
|---|---|
| `INVOKE %h, res, args, to, hb` | `START_TASK` + `START_TIMER`(timeout) + `START_TIMER`(heartbeat) + a `WAIT` loop |
| `SLEEP %s` | `START_TIMER` + `WAIT` |
| `RETRY` | `CALC` (backoff arithmetic) + `START_TIMER` + `WAIT` + `JMP` to `.attempt` |
| `BR_EQ` | `CALC %x, %a == %b` + `BR` |
| `FORK_MAP` / `FORK_PAR` | `GROUP_NEW` with different operands |
| `FORK_SPAWN` / `FORK_DONE` / `FORK_EXIT` / `FORK_CANCEL` / `FORK_RUNNING` / `FORK_ERR` / `FORK_RESULT` | `SPAWN` / `CALC` reading a group field / `SCOPE_CLOSE` |
| `RECV_CHILD` | `WAIT` with a `child-exit` message-kind source |
| `MKERR` / `ERR` | `EVAL` + `CALC` constructing the error object |
| `SETPADS` | the `cleanup=` operand of `ENTER` |

## 6. Invariants (implementation checklist)

1. Every operand of every instruction is defined; every referenced label exists in the program.
2. **Error edges are lexical.** Every instruction that can fail carries its own `!L` with an
   independent target — this is required because ASL wants "a Catcher's `Output`/`Assign`
   failure is uncatchable" expressed *per site*.
3. Register names are known at compile time; no runtime name lookup. `%in` flows one way through
   states.
4. **A group must live in a register** — the parent frame is suspended while children run, so the
   group must be persistable.
5. **One `SPAWN`, one child.** The limit is a comparison in the program plus a retry on child
   exit.
6. **A child's completion is a message**, not a shared-memory write.
7. Keys must be unique and stable across recovery; a child's key must include its frame identity.
8. Register values are serialized with type tags.
9. If a frame holds no live resource, its cleanup pad is omitted and cancel terminates it.

## 7. Comparison with the reference implementations

### 7.1 `third_party/asl-ir-demo/asl` (26 opcodes, full ASL front end + durability)

What is right and should be carried over:

- The **runtime skeleton**: event log + checkpoint + replay, the `Recorder` for nondeterministic
  functions (`$millis`/`$now`/`$random`/`$uuid`) recorded **in call order**, object fields
  evaluated **in key order** so replay is byte-identical, effects split into an outbox
  (`StartTask`/`CancelTask`/`StartTimer`), structured-concurrency assertion (a frame may not exit
  with live children), child threads deleted after handoff.
- **Type-tagged register serialization.** This is what answers "what can a register hold": a
  handle-like value is just a tagged register value, not a side table entry.
- `%in` / `%out` one-way flow, with `Output` and `Assign` both evaluated against **entry-time**
  variables and `Assign` committed at state exit.
- Per-state label blocks + `JMP` — structurally identical to one function per state returning the
  next state (§8.1).

What is wrong, by §2.1:

| asl | Verdict |
|---|---|
| `INVOKE` creates the timeout and heartbeat timers inside the interpreter, minting the key namespaces `timeout:`, `hb:`, `exec_timeout` that `Apply` dispatches on by string prefix | hidden semantics; also **internally inconsistent** — `SLEEP` puts a Wait's timer on the IR and `INVOKE` does not |
| `RETRY` opcode: `interval * rate^n`, `MaxDelaySeconds`, `MaxAttempts` computed in `case RETRY` | hidden domain rule |
| `FORK_EXIT` opcode: `Live` removal, `Running--`, status dispatch, **tolerance threshold arithmetic**, `Abort`/`Err` assignment, result-slot write | a whole slab of straight-line code implemented by the runtime |
| `FORK_SPAWN` opcode: spawns several children in one instruction, limit arithmetic inside | the limit belongs to the program |
| `Owner map[string]string` — a derived index over `Thread.Wait.Key`, persisted as first-class state | denormalized state that must be kept consistent by hand |
| Parent-child link recorded twice (`ForkState.Live` and `Thread.Children`) | same |
| `Beat.Seq` + the `hb:` namespace | a runtime-managed counter doing what an immutable handle does |
| Compiler emits `MOV %out,%in` then unconditionally `MOV %in,%out` | dead instruction when a state has no `Output` |
| A timed-out task's `timeout:` timer is not cancelled by `CancelTask`, so a useless event always arrives later and is dropped | unbounded event growth |

What asl gets right that this design keeps (§7.2): **Map and Parallel are already unified in its
compiler** — `forkLoop` is one function emitting the *same 15 instructions* for `FanOut`
(Parallel) and `ShipAll` (Map). The unification stops at the compiler; the runtime still has two
`case` blocks for initialisation and one large `case FORK_EXIT`.

### 7.2 Map and Parallel share one pseudocode

`runFanout` (§8.3) handles both; the entire difference is in `plan`:

| | Map | Parallel |
|---|---|---|
| N | `len(eval(Items))`, runtime | `len(Branches)`, **compile-time constant** |
| per-item input | `eval(ItemSelector, {Index, Value})` | the state's input, **identical for all** |
| per-item entry | `Entry`, identical for all | `Branches[i]`, all different |
| `MaxConcurrency` | optional | none = unlimited |
| tolerance | optional | none = first failure aborts |

Parallel is a **genuine degeneracy** of Map, not a forced merge: constant N, identity selector,
infinite limit, zero tolerance. Because `TolCount < 0 && TolPct < 0` is a compile-time constant
for Parallel, the tolerance branch disappears entirely — sharing costs Parallel nothing.

Two consequences:

- **The skeleton is identical for both**, differing only in `GROUP_NEW`'s operands.
- Sharing makes a compiler optimisation visible that asl cannot express: **Parallel with a
  static N and unlimited concurrency expands to N × `SPAWN` + N waits, deleting the loop and the
  limit comparison.** For n=2 that is shorter than the loop.

Pressure test — real ASL features that add nothing to the runtime:

- `ItemBatcher` → a third `plan` mode (N = `ceil(len(items)/batch)`, per-item input = a batch
  object).
- `ItemReader` (read items from S3) → **it is a `START_TASK` + `WAIT`**; `plan` starts by
  fetching the array. No new instruction.

### 7.3 `third_party/asl-ir-demo/scope` (11 opcodes, hand-written program)

The most lowered of the reference experiments, and the source of two things this design keeps:

- **`START_TIMER` as a real instruction**, which is what makes the three hardcoded key namespaces
  disappear.
- **`Handle` + `kinds` policy table** (`{cleanup actions, NeedAck}`), which is the answer to
  "what is a resource": asl has no such notion at all — its resource information is scattered
  across `Wait`, `Beat`, `Effect` and `Owner`, and it infers "is this timer still wanted" from
  `waiter(key) == nil`.

`scope` is **not** a complete replacement: it has no Map, no Parallel, no child frames, no
dynamic handle creation, no tolerance, and its `START_TASK` mints keys as
`State/Attempt/task`, which collides for N items. It also does not lower the cleanup path — its
`terminate` walks the scope stack in the runtime. Its instruction count is not its merit; its
**resource model** is.

### 7.4 Superseded opcodes

| Draft / asl opcode | Disposition |
|---|---|
| `SETPADS` | folded into `ENTER`'s `cleanup=` operand |
| `ATTEMPT` | folded into `ENTER` + the retry loop |
| `INVOKE` | macro (§5) |
| `SLEEP` | macro; must share the path with the Task timeout |
| `RETRY` | macro; backoff arithmetic moves into `CALC` |
| `FORK_MAP` / `FORK_PAR` | one `GROUP_NEW`, two operand sets |
| `FORK_SPAWN` / `FORK_DONE` / `FORK_RUNNING` / `FORK_ERR` / `FORK_RESULT` | `SPAWN` / `CALC` |
| `FORK_EXIT` | deleted; tolerance arithmetic is `CALC`, partly constant-folded |
| `FORK_CANCEL` + drain loop | `SCOPE_CLOSE` (waiting for acks is a generic mechanism) |
| `RECV_CHILD` | `WAIT` with a message-kind source |
| `MKERR` / `ERR` | `EVAL` + `CALC` |
| `JOIN` / `WAIT %g, ANY\|ALL` | not needed; the group's ok path is `MOV %res, %g.Results` |

## 8. Derivation appendix — reference implementations

These are the Go reference implementations the instruction set was derived from. Each row of §4
can be pointed back to a line here. They are deliberately written as in-process code that ignores
crashes; the derivation rule is:

> For each line ask: *if we crash right after this line, what must already be persisted to
> continue correctly?* That set is the IR.

### 8.1 Driver — one function per state

```go
// Each ASL state is a function; the transition is the return value.
// IR counterpart: one label block per state + JMP.
func (d *Driver) run(m *Machine, input any) (any, error) {
	vars := NewVars()                       // outer scope, shared across states
	state := m.StartAt
	for {
		out, next, err := d.step(m.States[state], input, vars)
		if err != nil { return nil, err }
		input = out
		if next == "" { return out, nil }   // End / Succeed
		state = next
	}
}
```

### 8.2 Task — where the suspensions are

```go
func (d *Driver) runTask(st *TaskState, input any, vars *Vars) (out any, next string, err error) {
	counts := map[int]int{}

	for {
		args, err := eval(st.Arguments, vars.With(input).Retry(counts))
		if err != nil { return nil, "", err }               // lexical error edge -> EVAL !L

		result, err := d.call(st.Resource, args, st.TimeoutSeconds, st.HeartbeatSeconds)
		if err == nil {
			out, err = eval(st.Output, vars.With(input).Result(result))
			if err != nil { return nil, "", err }
			if err = d.assign(st.Assign, vars.With(input).Result(result)); err != nil {
				return nil, "", err
			}
			return out, st.Next, nil
		}

		if delay, ok := backoff(st.Retry, err, counts); ok {  // -> CALC
			time.Sleep(delay)                                 // -> START_TIMER + WAIT
			continue
		}
		for _, c := range st.Catch {
			if !c.Matches(err) { continue }                   // -> MATCH
			// A Catcher's Assign/Output failure is uncatchable, so not `return ..., err`:
			if e := d.assign(c.Assign, vars.WithError(err)); e != nil {
				return nil, "", Terminal(e)                   // -> THROW
			}
			out, e := eval(c.Output, vars.WithError(err))
			if e != nil { return nil, "", Terminal(e) }
			return out, c.Next, nil
		}
		return nil, "", err
	}
}

func (d *Driver) call(resource string, args any, timeout, heartbeat int) (any, error) {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()                                    // cleanup: NOT executed on crash -> must be data

	task := d.startTask(ctx, resource, args)          // -> START_TASK

	tmoTimer := time.NewTimer(time.Duration(timeout) * time.Second)
	defer tmoTimer.Stop()                             // -> START_TIMER + scope
	beatTimer := time.NewTimer(time.Duration(heartbeat) * time.Second)
	defer beatTimer.Stop()

	hbLast := d.now()
	beat := beatTimer.C

	for {
		select {                                  // -> the ONLY suspension; its cases are WAIT's sources
		case r := <-task.Done():
			return r.Value, r.Err
		case <-tmoTimer.C:
			cancel()
			return nil, ErrTimeout                // States.Timeout
		case <-beat:
			if d.now()-hbLast < heartbeat {
				// The deadline is recomputed from the last heartbeat, not from now.
				beatTimer.Reset(time.Duration(hbLast+heartbeat-d.now()) * time.Second)
				beat = beatTimer.C
			} else {
				cancel()
				return nil, ErrHeartbeatTimeout
			}
		case hb := <-d.heartbeats:                // external heartbeat arrival
			if hb.Token == task.Token() { hbLast = d.now() }
		case <-ctx.Done():                        // execution timeout / StopExecution
			return nil, ErrCancelled
		}
	}
}
```

Four things this reveals:

1. **Go's `select` has four cases: three handles and one message channel.** `WAIT`'s sources must
   therefore be *heterogeneous* — a handle or a message kind. The heartbeat needs no special
   runtime property; it is just another case.
2. **Every `if err != nil { return ..., err }` is a lexical error edge**, and `Terminal(e)` shows
   that the uncatchable case must be expressible at the same site with a different target.
3. **`defer cancel()` / `defer t.Stop()` do not run on crash** — hence §2.3.
4. **`time.Sleep(delay)` is `START_TIMER` + `WAIT`**, i.e. the same path as the Task timeout.

### 8.3 Map / Parallel — one implementation

```go
// Fanout covers both ASL Map and Parallel: "N child machines in parallel + a result array".
type Fanout struct {
	Items    any      // Map:      Items expression
	Selector any      // Map:      ItemSelector
	Entry    string   // Map:      ItemProcessor.StartAt
	Branches []string // Parallel: branch entries; its length is N

	MaxConc  int     // Parallel: 0 = unlimited
	TolCount int     // Parallel: -1 = unset
	TolPct   float64 // Parallel: -1 = unset
}

// plan is the ONLY place Map and Parallel differ.
func (d *Driver) plan(st *Fanout, input any, vars *Vars) (inputs []any, entries []string, err error) {
	if st.Branches != nil {                        // Parallel: constant N, identical inputs
		inputs = make([]any, len(st.Branches))
		for i := range inputs { inputs[i] = input }
		return inputs, st.Branches, nil
	}
	items, err := eval(st.Items, vars.With(input))  // Map: N known only at runtime
	if err != nil { return nil, nil, err }
	arr, ok := items.([]any)
	if !ok { return nil, nil, StateError{"States.QueryEvaluationError", "Items must be an array"} }

	inputs = make([]any, len(arr))
	for i, it := range arr {
		inputs[i], err = eval(st.Selector, vars.MapItem(i, it))
		if err != nil { return nil, nil, err }
	}
	entries = make([]string, len(arr))
	for i := range entries { entries[i] = st.Entry }
	return inputs, entries, nil
}

// runFanout is identical for Map and Parallel.
func (d *Driver) runFanout(st *Fanout, input any, vars *Vars) (out any, next string, err error) {
	inputs, entries, err := d.plan(st, input, vars)
	if err != nil { return nil, "", err }
	n := len(inputs)

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	g, gctx := errgroup.WithContext(ctx)
	if st.MaxConc > 0 { g.SetLimit(st.MaxConc) }    // <- hides a suspension inside a call

	results := make([]any, n)
	var mu sync.Mutex
	failed := 0

	for i := 0; i < n; i++ {
		i := i
		g.Go(func() error {                        // <- one goroutine = one child frame
			r, err := d.run(gctx, entries[i], inputs[i])
			mu.Lock(); defer mu.Unlock()
			if err == nil { results[i] = r; return nil }
			results[i] = err.AsErrorOutput()
			if st.TolCount < 0 && st.TolPct < 0 { return err }   // first failure aborts
			failed++
			if exceeded(st, failed, n) {
				return StateError{"States.ExceedToleratedFailureThreshold",
					fmt.Sprintf("%d of %d items failed", failed, n)}
			}
			return nil
		})
	}

	if err := g.Wait(); err != nil { return nil, "", err }       // <- drain
	out, err = eval(st.Output, vars.With(input).Result(results))
	if err != nil { return nil, "", err }
	if err = d.assign(st.Assign, vars.With(input).Result(results)); err != nil { return nil, "", err }
	return out, st.Next, nil
}
```

Five things the in-process version hides, and what the IR must do instead:

| Hidden in Go | Why it cannot be in a durable IR |
|---|---|
| `g.SetLimit(n)` blocks inside a function call | you cannot suspend inside a call; the limit becomes a comparison in the program plus a retry on each child exit |
| `results` + `mu` are shared memory | the parent is **suspended** while children run; a child's write must be a message, applied by the parent after `WAIT` |
| `g.Wait()` is one-step drain | draining is: signal every live child, then wait for each acknowledgement |
| the closure captures `vars` by reference | siblings would see each other's `assign`; the outer scope must be **snapshotted** at `SPAWN` |
| which item trips the threshold depends on scheduling | in the IR it is the event order, hence deterministic. The Go version's semantics are *weaker* than ASL's, not stronger |

**Correction to an earlier claim:** `MaxConcurrency` does *not* need a semaphore resource. Go needs
blocking because its parent goroutine runs a synchronous loop with no event loop; in the durable
setting the slot's release event (a child exiting) is already visible, so the limit is a
comparison in the program.

## 9. Open Questions

**OPEN-1. Simultaneous-source tie-break.** When two sources become ready at once, which does
`WAIT` return — event-log order (asl's behaviour, which leaks the decision into the durability
layer, since it depends on which event was written to the inbox first), or a fixed rule (BEAM's
`receive...after` gives message priority)?

**OPEN-2. Cleanup landing pad vs. scope walking.** A `%cleanup` register chain (fully fixed in the
IR), or the runtime walking the frame's scope stack (bounded bookkeeping, but then the landing
point is not data). Both satisfy §2.3; the choice decides which part is program and which is
mechanism.

**OPEN-3. Re-run or persist `pc`.** The external-cancel jump is either `JMP %cleanup` (persist
`pc`, M2a as asl does), or re-run from the last suspension point with cancellation injected (M1 —
then intermediate values need not enter registers at all).

**OPEN-4. Heartbeat handle shape.** `RESET %h, deadline` (mutable handle) or a repeated
`START_TIMER %h2` (immutable handles — asl's `Seq` is already doing this, just hidden in the
runtime and dragging the `hb:` namespace with it).

**OPEN-5. `ItemSelector`: per-item or hoisted.** asl hoists (evaluate all, then spawn), which
makes a selector failure a **Map-level** error that tolerance cannot absorb. AWS evaluates per
item, making it that item's failure.

**OPEN-6. Tolerance details.** `ToleratedFailurePercentage` denominator (total items vs. completed
so far — asl uses the total); the default when the fields are unset (`0` vs. "unset" differ for
the percentage computation); what goes in the result slot of an item cancelled by an abort
(`null` as asl does, or nothing).

**OPEN-7. Where `MATCH` lives.** Whether ASL's error-name rules move into `CALC`'s expression
language (one instruction fewer, but the expression language then carries domain semantics).

**OPEN-8. A third pads register.** Whether `SCOPE_CLOSE`'s "waiting for acknowledgements" needs
its own landing point (`%cln_done`).

**OPEN-9. Unification candidates not yet decided.** Whether `CANCEL_ALL` should exist separately
from `SCOPE_CLOSE` given that a group's live children are a scope's handles; whether `JOIN` is
ever needed; whether `MOV` / `BR_EQ` / `MATCH` should be de-sugared away entirely.

**OPEN-10. Nested fan-out key uniqueness.** A Map inside a Parallel branch (the `fanout` scenario)
must produce unique, recovery-stable keys at every nesting level.
